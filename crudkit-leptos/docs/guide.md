CrudKit's Leptos frontend: the state of CRUD screens as hooks, and atoms to build them from.

CrudKit ships no prebuilt screens and no theme. An application builds every screen of a resource (its list, create,
edit, and read views) from atoms, in its own markup and styles. The atoms carry CrudKit's behavior: loading, paging,
sorting, selection, drafts, validation, saving, deletion, confirmations, and actions. Everything around them is the
application's. This guide explains everything needed to build such a UI.

The examples use a `clubs` resource with `players` nested in each club. Its models and configuration are defined in
[Resources and configuration](#resources-and-configuration).

# Setup

An application depends on `crudkit-leptos` and on [Leptonic](https://github.com/lpotthast/leptonic)'s `hooks` branch,
whose atoms it composes with CrudKit's (`Input`, `Label`, `ModalContent`, `Toast`, ...). CrudKit uses neither
Leptonic's themed components nor its theme. Server builds enable the `ssr` features and client builds the `hydrate`
features of `crudkit-leptos` and Leptonic, next to Leptos' own:

```toml
[dependencies]
crudkit-leptos = { path = "../crudkit/crudkit-leptos" }
leptonic = { path = "../leptonic/leptonic", default-features = false, features = ["atoms"] }
leptos = "0.8"
serde = { version = "1", features = ["derive"] }
# Code generated by the `CkField` derive refers to it.
typetag = "0.2"

[features]
ssr = ["crudkit-leptos/ssr", "leptonic/ssr", "leptos/ssr"]
hydrate = ["crudkit-leptos/hydrate", "leptonic/hydrate", "leptos/hydrate"]
```

Leptonic needs unstable `web-sys` APIs, so builds pass `--cfg=web_sys_unstable_apis`, e.g. in `.cargo/config.toml`:

```toml
[build]
rustflags = ["--cfg=web_sys_unstable_apis"]
```

The server side of a resource is `crudkit-rs`, which serves its REST API. An instance sends its requests to
`{api_base_url}/{resource_name}/crud/v1/...` through a `ReqwestExecutor`. Date-time values must serialize the same
on the server and in the browser, e.g. with `time`'s `serde-human-readable` feature on both.

# Resources and configuration

A resource has three models, each deriving `CkField` for its role: the update model (which also derives `CkResource`
and `CkId`), the create model, and the read model the list shows. The derives generate a field enum per model, e.g.
`Club::Name`, through which configuration and atoms name fields.

```no_run
use crudkit_leptos::prelude::*;
use serde::{Deserialize, Serialize};

#[derive(Clone, PartialEq, Eq, Debug, CkId, CkField, CkResource, Serialize, Deserialize)]
#[ck_resource(resource_name = "clubs")]
#[ck_field(model = Update)]
pub struct Club {
    pub id: i64,
    pub name: String,
    /// Not stored: a field showing the club's players, see "Nested resources".
    #[serde(skip_deserializing)]
    pub players: (),
}

#[derive(Clone, PartialEq, Eq, Debug, Default, CkField, Serialize, Deserialize)]
#[ck_field(model = Create)]
pub struct CreateClub {
    pub name: String,
}

impl ErasedIdentifiable for CreateClub {
    fn id(&self) -> SerializableId {
        unreachable!("create models have no id")
    }
}

#[derive(Clone, PartialEq, Eq, Debug, CkId, CkField, Serialize, Deserialize)]
#[ck_field(model = Read)]
pub struct ReadClub {
    pub id: i64,
    pub name: String,
}

impl From<ReadClub> for Club {
    fn from(read: ReadClub) -> Self {
        Self { id: read.id, name: read.name, players: () }
    }
}
# fn main() {}
```

A [`CrudInstanceConfig`](config::CrudInstanceConfig) describes how the resource is shown: the list's columns
([`Header`](config::Header)s with their `HeaderOptions`: display name, whether the column sorts, date-time display),
the create layout (`create_elements`) and the layout of the edit and read views (`elements`), the initial ordering and
page size, actions, and field renderers. Layouts are `Elem`s: fields with `FieldOptions` (label, whether the field is
disabled, date-time display), separators, and groups laid out in one to four columns, possibly as a card or tabs.
[`CrudInstanceConfig::new`](config::CrudInstanceConfig::new) starts from defaults:

```no_run
# crudkit_leptos::__doc_example!();
# use indexmap::indexmap;
fn options(label: &'static str) -> FieldOptions {
    FieldOptions { label: Some(Label::new(label)), ..FieldOptions::default() }
}

fn clubs_config() -> CrudInstanceConfig {
    CrudInstanceConfig {
        list_columns: vec![
            Header::showing(ReadClub::Id, HeaderOptions { display_name: "#".into(), ..HeaderOptions::default() }),
            Header::showing(ReadClub::Name, HeaderOptions { display_name: "Name".into(), ..HeaderOptions::default() }),
        ],
        create_elements: vec![Elem::create_field(CreateClub::Name, options("Name"))],
        elements: vec![Elem::Enclosing(Enclosing::Tabs(vec![
            Tab {
                id: "club".into(),
                label: Label::new("Club"),
                group: Group {
                    layout: Layout::Columns2,
                    children: vec![
                        Elem::field(Club::Id, FieldOptions { disabled: true, ..options("ID") }),
                        Elem::field(Club::Name, options("Name")),
                    ],
                },
            },
            Tab {
                id: "players".into(),
                label: Label::new("Players"),
                group: Group {
                    layout: Layout::Columns1,
                    children: vec![Elem::field(Club::Players, options("Players"))],
                },
            },
        ]))],
        order_by: indexmap! { ReadClub::Name.into() => Order::Asc },
        ..CrudInstanceConfig::new::<CrudClubResource>(
            "/api",
            std::sync::Arc::new(crudkit_web::http::NewClientPerRequestExecutor),
        )
    }
}
# fn main() {}
```

# Layers

- [`config`]: what an application declares per resource: columns, form layouts, actions, field renderers, views,
  texts. Plain data, no markup apart from the renderers an application registers.
- [`instance`]: the runtime of a mounted resource: [`CrudInstanceMgr`](instance::CrudInstanceMgr),
  [`CrudInstance`](instance::CrudInstance), navigation between views, and [`CrudViewOutlet`](instance::CrudViewOutlet).
- [`hooks`]: CrudKit's behavior as reactive state, e.g. [`use_crud_list`](hooks::use_crud_list) or
  [`use_crud_form`](hooks::use_crud_form). Everything the atoms do is reachable through hooks.
- [`atoms`]: components binding that state to markup.

# Atoms

CrudKit's atoms follow the rules of Leptonic's atoms, and are combined with them:

- **One element.** An atom renders exactly one element, so the application decides everything around it. Providers
  ([`CrudInstance`](instance::CrudInstance), [`CrudList`](atoms::CrudList), [`CrudField`](atoms::CrudField)),
  outlets, and iterators render no element at all. Action buttons also render their action's view (an overlay, such
  as a dialog asking for input) after their button.
- **Default classes and data attributes.** An atom's element carries the class `crudkit-` plus the atom's name without
  its `Crud` prefix (`CrudSaveButton` renders `class="leptonic-Button crudkit-SaveButton"`), and its state as `data-*`
  attributes that are absent when false (`data-dirty`, `data-sort-direction="ascending"`, ...). Each atom documents
  both. `classes` and `styles` add to them.
- **Context instead of props.** Atoms find what they act on in context: the instance, the list, the form, the field,
  the table row. A [`CrudDeleteButton`](atoms::CrudDeleteButton) deletes the entity of the row or form it is in. Props
  override the context where that makes sense. A nested [`CrudInstance`](instance::CrudInstance) hides the table rows,
  forms, and entities around it, so the atoms inside act on the nested instance only. Atoms that need a container (a
  list, table, field, or dialog) use the nearest one, so give a nested instance its own. An atom rendered outside its
  container panics with a message naming it.
- **Leptonic atoms where they fit.** Field atoms bind a field to Leptonic's field atoms, whose parts (`Label`,
  `Input`, `TextArea`, `Description`, `FieldError`) the application places inside. Buttons are Leptonic `Button`s,
  dialogs are Leptonic `ModalBackdrop`s, and the page size is a Leptonic `Select`.
- **Sensible defaults.** Atoms that show text show CrudKit's localizable texts (see [Texts](#texts)) unless given
  children. Iterators render their one obvious atom, e.g. [`CrudTableCells`](atoms::CrudTableCells) a
  [`CrudTableCell`](atoms::CrudTableCell) per column.

# Mounting a resource

A [`CrudInstanceMgr`](instance::CrudInstanceMgr) hosts the instances of a page. A
[`CrudInstance`](instance::CrudInstance) mounts one configured resource, and its
[`CrudViewOutlet`](instance::CrudViewOutlet) renders the current view (list, create, edit, read, or one of the
application's own) with the renderer registered for it in a [`CrudViewRegistry`](config::CrudViewRegistry).
Confirmation dialogs belong next to the outlet, so they serve every view of the instance.

```no_run
# crudkit_leptos::__doc_example!();
#[component]
fn ClubsPage() -> impl IntoView {
    // The views of every instance below, unless an instance's configuration sets its own.
    provide_crud_view_registry(
        CrudViewRegistry::default()
            .table(|| view! { <ListView/> })
            .create(|| view! { <CreateView/> })
            .edit(|id| view! { <EditView id/> })
            .read(|id| view! { <ReadView id/> }),
    );
    view! {
        <CrudInstanceMgr>
            <CrudInstance name="clubs" config=club_config()>
                <CrudViewOutlet/>
                <Confirmations/>
            </CrudInstance>
        </CrudInstanceMgr>
    }
}
# #[component] fn ListView() -> impl IntoView {}
# #[component] fn CreateView() -> impl IntoView {}
# #[component] fn EditView(id: SerializableId) -> impl IntoView {}
# #[component] fn ReadView(id: SerializableId) -> impl IntoView {}
# #[component] fn Confirmations() -> impl IntoView {}
# fn main() {}
```

Views find their instance and navigation in context. The registry's typed methods check that a view is opened with
the subject it needs (an entity id for `edit` and `read`, none otherwise) and show a visible error otherwise. A
registry is empty by default: a view without a renderer shows a visible error. Instance names are unique per manager;
nested resources find their parent instance by name.

# A list view

[`CrudList`](atoms::CrudList) loads the current page of the instance's entities and provides the list to the table,
pagination, and selection atoms inside it. The table is an accessible grid: arrow keys move between cells, column
headers sort, rows are selected through their checkboxes, and activating a row runs its
[`CrudRowAction`](atoms::CrudRowAction).

```no_run
# crudkit_leptos::__doc_example!();
#[component]
fn ListView() -> impl IntoView {
    view! {
        <CrudList>
            <div class="toolbar">
                <CrudSelectionCount/>
                <CrudDeleteSelectedButton/>
                <CrudResourceActions/>
                <CrudCreateButton/>
            </div>
            <CrudTable selectable=true with_actions=true row_action=CrudRowAction::Edit>
                <CrudTableHeader>
                    <CrudTableHeaderRow>
                        <CrudTableSelectAllHeader>
                            <CrudSelectAllCheckbox/>
                        </CrudTableSelectAllHeader>
                        <CrudTableColumnHeaders/>
                        <CrudTableActionsHeader/>
                    </CrudTableHeaderRow>
                </CrudTableHeader>
                <CrudTableBody>
                    <CrudTableRows>
                        <CrudTableRow>
                            <CrudTableSelectionCell>
                                <CrudRowCheckbox/>
                            </CrudTableSelectionCell>
                            <CrudTableCells/>
                            <CrudTableActionsCell>
                                <CrudReadButton/>
                                <CrudEditButton/>
                                <CrudDeleteButton/>
                            </CrudTableActionsCell>
                        </CrudTableRow>
                    </CrudTableRows>
                </CrudTableBody>
            </CrudTable>
            <CrudListStatus/>
            <CrudPagination>
                <CrudPreviousPageButton/>
                <CrudPageButtons/>
                <CrudNextPageButton/>
            </CrudPagination>
        </CrudList>
    }
}
# fn main() {}
```

[`CrudTable`](atoms::CrudTable) shows the instance's configured columns. Its `selectable` and `with_actions` props add
the selection and actions columns, whose header and cells the rows then render; the selection atoms panic in a table
that is not selectable. The table's accessible name defaults to the resource name; give it a better one with
`aria_label` or `aria_labelledby`. Inside a row, [`use_crud_table_row`](hooks::use_crud_table_row) returns its entity,
the instance's read model.

A cell shows the read renderer registered for its field (see [Field renderers](#field-renderers)), else the value as
text ([`CrudValue`](atoms::CrudValue)). To arrange or decorate cells individually, render them yourself instead of
[`CrudTableCells`](atoms::CrudTableCells):

```no_run
# crudkit_leptos::__doc_example!();
#[component]
fn ClubRow() -> impl IntoView {
    let club = use_crud_table_row();
    let href = move || format!("/clubs/{}", club.read().downcast_ref::<ReadClub>().id);
    view! {
        <CrudTableRow>
            <CrudTableCell column=ReadClub::Name classes="name"/>
            <CrudTableCell column=ReadClub::Id>
                <a href=href>"Open"</a>
            </CrudTableCell>
        </CrudTableRow>
    }
}
# fn main() {}
```

[`CrudListStatus`](atoms::CrudListStatus) explains a list that is loading, empty, or failed to load, with CrudKit's
texts or markup of your own per case. The page size is chosen with [`CrudItemsPerPage`](atoms::CrudItemsPerPage), a
Leptonic `Select` composed of Leptonic's select parts, whose options
[`CrudItemsPerPageOptions`](atoms::CrudItemsPerPageOptions) renders:

```no_run
# crudkit_leptos::__doc_example!();
use leptonic::atoms::prelude::{Label, ListBox, SelectPopover, SelectTrigger, SelectValue};

#[component]
fn ListFooter() -> impl IntoView {
    view! {
        <CrudListStatus empty=|| view! { <strong>"No clubs yet."</strong> }/>
        <CrudItemsPerPage>
            <Label>"Clubs per page"</Label>
            <SelectTrigger>
                <SelectValue/>
            </SelectTrigger>
            <SelectPopover>
                <ListBox>
                    <CrudItemsPerPageOptions/>
                </ListBox>
            </SelectPopover>
        </CrudItemsPerPage>
    }
}
# fn main() {}
```

[`CrudClearSelectionButton`](atoms::CrudClearSelectionButton) clears the selection and
[`CrudResetButton`](atoms::CrudResetButton) resets the instance to its configured page, page size, ordering, and
view. Buttons of your own acting on the entity of the surrounding row or form read it with
[`use_crud_entity`](hooks::use_crud_entity), and [`use_crud_list`](hooks::use_crud_list) gives markup of your own the
list's rows, count, paging, ordering, and selection, e.g. for a summary like "21-30 of 57"
([`CrudPaginationState::range`](hooks::CrudPaginationState::range)).

# Create, edit, and read views

[`CrudCreateForm`](atoms::CrudCreateForm), [`CrudEditForm`](atoms::CrudEditForm), and
[`CrudDetails`](atoms::CrudDetails) hold one entity's draft (or, for details, its read-only values) and provide it to
the fields and buttons inside. Their element exposes `data-status` (`loading`, `ready`, `not-found`, `failed`), and
the forms `data-dirty` and `data-saving`.

```no_run
# crudkit_leptos::__doc_example!();
#[component]
fn CreateView() -> impl IntoView {
    view! {
        <CrudCreateForm>
            <header>
                <CrudReturnButton/>
                <h2>"New club"</h2>
            </header>
            <CrudFormLayout/>
            <footer>
                <CrudSaveButton follow_up=CrudSaveFollowUp::CreateAnother/>
                <CrudSaveButton/>
            </footer>
        </CrudCreateForm>
    }
}

#[component]
fn EditView(id: SerializableId) -> impl IntoView {
    view! {
        <CrudEditForm id>
            <header>
                <CrudReturnButton/>
                <h2>"Edit club"</h2>
                <CrudEntityActions/>
            </header>
            <CrudEntityStatus/>
            <CrudFormLayout/>
            <footer>
                <CrudDeleteButton/>
                <CrudSaveButton follow_up=CrudSaveFollowUp::Return/>
                <CrudSaveButton/>
            </footer>
        </CrudEditForm>
    }
}

#[component]
fn ReadView(id: SerializableId) -> impl IntoView {
    view! {
        <CrudDetails id mode=FieldMode::Display>
            <header>
                <CrudReturnButton/>
                <h2>"Club"</h2>
                <CrudEditButton/>
            </header>
            <CrudEntityStatus/>
            <CrudFormLayout/>
        </CrudDetails>
    }
}
# fn main() {}
```

[`CrudEntityStatus`](atoms::CrudEntityStatus) explains an entity that is loading, missing, or failed to load; each
case can show markup of its own, e.g. a loading skeleton. [`CrudFormLayout`](atoms::CrudFormLayout) renders the
layout configured for the form: groups as [`CrudFormGroup`](atoms::CrudFormGroup)s (with `data-columns`), cards as
[`CrudFormCard`](atoms::CrudFormCard)s, tabs as [`CrudFormTabs`](atoms::CrudFormTabs) of
[`CrudFormTab`](atoms::CrudFormTab)s and [`CrudFormTabPanel`](atoms::CrudFormTabPanel)s, separators as
[`CrudFormSeparator`](atoms::CrudFormSeparator)s, and each field as a [`CrudFieldControl`](atoms::CrudFieldControl).
Its `*_classes` props style these elements, e.g. `group_classes="grid gap-4"`. A view that wants other markup places
its fields itself (see [Fields](#fields)), and composes tabs from the same atoms:

```no_run
# crudkit_leptos::__doc_example!();
use leptonic::atoms::prelude::TabList;

#[component]
fn ClubTabs() -> impl IntoView {
    let tabs = vec![
        CrudTab { id: "club".into(), label: "Club".to_owned() },
        CrudTab { id: "players".into(), label: "Players".to_owned() },
    ];
    view! {
        <CrudFormTabs tabs>
            <TabList>
                <CrudFormTab id=TabId::from("club")/>
                <CrudFormTab id=TabId::from("players")/>
            </TabList>
            <CrudFormTabPanel id=TabId::from("club") should_force_mount=true>
                <CrudField field=Club::Name>
                    <CrudFieldControl/>
                </CrudField>
            </CrudFormTabPanel>
            <CrudFormTabPanel id=TabId::from("players") should_force_mount=true>
                <CrudField field=Club::Players>
                    <CrudFieldControl/>
                </CrudField>
            </CrudFormTabPanel>
        </CrudFormTabs>
    }
}
# fn main() {}
```

The instance remembers the selected tab of every tab group, also across views. A force-mounted panel keeps its fields
mounted while another tab is shown, so input that cannot be read yet survives switching tabs.

[`CrudSaveButton`](atoms::CrudSaveButton) saves the draft, then follows its
[`CrudSaveFollowUp`](hooks::CrudSaveFollowUp): by default, a created entity opens in the edit view and an edited one
stays. A save button without a `follow_up` of its own is the form's submit button, so pressing Enter in a field saves
the form the same way; its text follows its follow-up. The form's fields are read-only while it saves. While a form
has unsaved changes, leaving its view asks for confirmation (see [Confirmations](#confirmations)), and a reload of its
entity keeps those changes. Saving notifies its outcome (see [Notifications](#notifications)), as the form's
`notifications` prop selects; `on_saved` and `on_save_failed` let the view react itself.
[`use_crud_form`](hooks::use_crud_form) returns the surrounding form, e.g. to show its dirty state, its save
violations, or a skeleton while it loads.

HTML forms cannot nest: a form atom inside another one, e.g. of a nested resource shown in a field, renders a
`<div role="group">` instead, which saves on Enter in one of its inputs.

# Fields

[`CrudField`](atoms::CrudField) binds one field of the surrounding form. Inside it, a field atom binds the field's
value, error, and state to the matching Leptonic field atom, and the application composes that atom's parts:

```no_run
# crudkit_leptos::__doc_example!();
# use leptonic::atoms::prelude::Input;
# #[component] fn NameField() -> impl IntoView { view! {
<CrudField field=Club::Name>
    <CrudTextField>
        <CrudFieldLabel/>
        <Input/>
        <CrudFieldError/>
    </CrudTextField>
</CrudField>
# } }
# fn main() {}
```

- [`CrudTextField`](atoms::CrudTextField) binds a Leptonic `TextField`: strings, and JSON, UUIDs, dates, and
  durations edited as text. Multiline values (JSON) use a Leptonic `TextArea` instead of an `Input`.
- [`CrudNumberField`](atoms::CrudNumberField) binds a Leptonic `NumberField` of the field's number type: all integer
  and float types, without grouping digits unless given `format_options`.
- [`CrudSwitch`](atoms::CrudSwitch) and [`CrudCheckbox`](atoms::CrudCheckbox) bind a Leptonic `Switch` or
  `Checkbox`: `bool`.
- [`CrudDisplayField`](atoms::CrudDisplayField) shows a field without editing it, e.g. in read views: a group of its
  label and a [`CrudFieldValue`](atoms::CrudFieldValue), the value as text.

[`CrudFieldLabel`](atoms::CrudFieldLabel) shows the label the field's options give, else the field's name.
[`CrudFieldError`](atoms::CrudFieldError) shows why the field's input could not be read. A field's options and mode
default to the ones the form's layout gives it; inside [`CrudDetails`](atoms::CrudDetails) fields are read-only, or
plain text with `mode=FieldMode::Display`.

[`CrudFieldControl`](atoms::CrudFieldControl) picks the markup for the field in context: the
[`FieldRenderer`](config::FieldRenderer) registered for it in the instance configuration, else the composition above
with the field atom matching the field's value kind. Each input kind can be replaced, e.g. to show checkboxes instead
of switches in every form layout:

```no_run
# crudkit_leptos::__doc_example!();
# #[component] fn Fields() -> impl IntoView { view! {
<CrudFormLayout field=|| view! {
    <CrudFieldControl toggle=|| view! { <CrudCheckbox/> }/>
}/>
# } }
# fn main() {}
```

[`use_crud_field_binding`](hooks::use_crud_field_binding) returns the field in context, e.g. to choose markup by its
kind (`CrudInputKind::of(binding.value_kind)`) or to give fields with a registered renderer more room
(`binding.has_renderer`).

# Field renderers

A [`FieldRenderer`](config::FieldRenderer) registered in the instance configuration renders one field wherever the
instance shows it: in every [`CrudFieldControl`](atoms::CrudFieldControl), and, for read renderers, in the table's
cells. It receives the field's [`CrudFieldState`](hooks::CrudFieldState), runs once, and binds field atoms or hooks
inside. A renderer rendering `<CrudFieldControl/>` gets the default markup, so it can decorate it:

```no_run
# crudkit_leptos::__doc_example!();
fn with_renderers(config: CrudInstanceConfig) -> CrudInstanceConfig {
    CrudInstanceConfig {
        // Table cells of the name column.
        read_field_renderer: FieldRendererRegistry::default().register(
            ReadClub::Name,
            FieldRenderer::new(|_| view! { <strong><CrudFieldValue/></strong> }),
        ),
        // The name field of the edit and read views, with a hint below the default markup.
        update_field_renderer: FieldRendererRegistry::default().register(
            Club::Name,
            FieldRenderer::new(|_| view! {
                <CrudFieldControl/>
                <small>"Shown on the league table."</small>
            }),
        ),
        ..config
    }
}
# fn main() {}
```

Fields holding lists or custom types have no default markup: they show a visible configuration error until a
renderer is registered.

# Nested resources

A resource can be shown inside an entity of another, e.g. a club's players inside the club's edit view: a field
renderer of the parent mounts another [`CrudInstance`](instance::CrudInstance) with a
[`CrudParentConfig`](config::CrudParentConfig). It names the parent instance and the fields linking both; the nested
instance then lists only the entities referencing the parent's entity and fills in the reference when creating one.
The nested instance needs its own outlet and dialogs, and its views sit below the parent's heading:

```no_run
# crudkit_leptos::__doc_example!();
fn nested_players() -> FieldRenderer<DynUpdateField> {
    FieldRenderer::new(|_| {
        let parent = Some(CrudParentConfig {
            name: "clubs",
            referenced_field: Club::Id.name(),
            referencing_field: Player::ClubId.name(),
        });
        view! {
            <h3>"Players"</h3>
            <CrudInstance name="club_players" config=player_config() parent>
                <CrudViewOutlet/>
                // Dialogs of the nested instance, like those of the parent.
            </CrudInstance>
        }
    })
}
# fn main() {}
```

The renderer's [`CrudFieldState`](hooks::CrudFieldState) tells whether the parent is edited (`state.mode`): in a read
view, an application typically shows the nested entities without the controls changing them.

# Views and navigation

[`use_crud_navigation`](hooks::use_crud_navigation) returns the navigation of the current view. Navigating opens
another view of the instance and asks for confirmation while a form of the current view has unsaved changes:

```no_run
# crudkit_leptos::__doc_example!();
#[component]
fn OpenAudit() -> impl IntoView {
    let navigation = use_crud_navigation();
    view! {
        <button on:click=move |_| { navigation.navigate(CrudView::new("app.audit")); }>
            "Audit"
        </button>
    }
}

fn registry() -> CrudViewRegistry {
    let mut registry = CrudViewRegistry::default().table(|| view! { <OpenAudit/> });
    registry
        .register("app.audit", |_view: CrudView| view! { <h2>"Audit"</h2> })
        .expect("the view name is unique");
    registry
}
# fn main() {}
```

Application-defined views receive the opened [`CrudView`](crudkit_web::view::CrudView), with an optional entity
subject and a serializable payload. [`CrudViewOutlet`](instance::CrudViewOutlet) renders the views of another
navigation when given one, e.g. a child navigation of the instance shown in a drawer. Each opened view mounts afresh.

# Confirmations

Deleting asks for confirmation, and so does leaving a view with unsaved changes. Place the dialogs once per instance,
next to its [`CrudViewOutlet`](instance::CrudViewOutlet); a nested instance needs dialogs of its own. A confirmation
that becomes pending without its dialog mounted is logged as an error, as the user could not answer it.
[`CrudDeleteDialog`](atoms::CrudDeleteDialog), [`CrudDeleteManyDialog`](atoms::CrudDeleteManyDialog), and
[`CrudLeaveDialog`](atoms::CrudLeaveDialog) are Leptonic `ModalBackdrop`s, open while their confirmation is pending.
Pressing Escape or outside of them cancels, except while the confirmed deletion runs. Compose them with Leptonic's
modal atoms and CrudKit's confirmation atoms, which show the matching texts:
[`CrudConfirmationTitle`](atoms::CrudConfirmationTitle), [`CrudConfirmationMessage`](atoms::CrudConfirmationMessage),
[`CrudCancelButton`](atoms::CrudCancelButton), and [`CrudConfirmButton`](atoms::CrudConfirmButton) (pending while the
deletion runs):

```no_run
# crudkit_leptos::__doc_example!();
use leptonic::atoms::prelude::{Dialog, ModalContent};
use leptonic::hooks::DialogRole;

#[component]
fn Confirmations() -> impl IntoView {
    view! {
        <CrudDeleteDialog>
            <ModalContent>
                <Dialog role=DialogRole::AlertDialog>
                    <CrudConfirmationTitle/>
                    <CrudConfirmationMessage/>
                    <CrudCancelButton/>
                    <CrudConfirmButton/>
                </Dialog>
            </ModalContent>
        </CrudDeleteDialog>
        // Likewise `CrudDeleteManyDialog` and `CrudLeaveDialog`.
    }
}
# fn main() {}
```

# Actions

Resource actions ([`actions`](config::CrudInstanceConfig::actions)) act on the resource, entity actions
([`entity_actions`](config::CrudInstanceConfig::entity_actions)) on the entity of the surrounding form, including its
unsaved changes. [`CrudResourceActions`](atoms::CrudResourceActions) renders a
[`CrudActionButton`](atoms::CrudActionButton) per resource action, and [`CrudEntityActions`](atoms::CrudEntityActions)
a [`CrudEntityActionButton`](atoms::CrudEntityActionButton) per entity action the form offers. A button shows the
action's icon and name and its `data-intent`. An action runs until it reports its outcome through `and_then`, which
may notify and reload the instance's data:

```no_run
# crudkit_leptos::__doc_example!();
fn reload() -> CrudAction {
    CrudAction {
        id: "reload",
        name: "Reload".to_owned(),
        icon: None,
        intent: CrudActionIntent::Secondary,
        action: Callback::new(|input: ResourceActionInput| {
            input.and_then.run(Ok(CrudActionAftermath {
                notification: Some(CrudNotification::info("Clubs", "The list was reloaded.")),
                reload_data: true,
            }));
        }),
        view: None,
    }
}
# fn main() {}
```

An action with a `view` (e.g. a dialog asking for its payload) shows it when pressed; the view is an overlay, rendered
by the button, which executes the action with the payload it collects.

# Notifications

Saving, deleting, and actions report their outcome as [`CrudNotification`](hooks::CrudNotification)s, each naming the
instance that sent it as its [`origin`](hooks::CrudNotification::origin). They go to one sink for the whole
application, provided once at its root, typically a Leptonic toast queue. Successes and information close after five
seconds; warnings and errors stay until closed. Requests completing after their view or instance unmounted still
notify.

```no_run
# crudkit_leptos::__doc_example!();
use leptonic::atoms::prelude::{
    Toast, ToastCloseButton, ToastContent, ToastDescription, ToastRegion, ToastTitle,
};
use leptonic::hooks::ToastQueue;

#[component]
fn App(children: Children) -> impl IntoView {
    let toasts = ToastQueue::<CrudNotification>::new(Some(5));
    provide_crud_notifier(CrudNotifier::toasts(toasts));
    view! {
        <CrudInstanceMgr>{children()}</CrudInstanceMgr>
        <ToastRegion queue=toasts let:toast>
            <Toast toast=toast.clone()>
                <ToastContent>
                    <ToastTitle>{toast.content.title.clone()}</ToastTitle>
                    <ToastDescription>{toast.content.message.clone()}</ToastDescription>
                </ToastContent>
                <ToastCloseButton>"×"</ToastCloseButton>
            </Toast>
        </ToastRegion>
    }
}
# fn main() {}
```

# Texts

Atoms show CrudKit's texts unless given children: button labels, statuses, dialog texts, accessible names, and the
messages of notifications. Provide them once with [`provide_crud_texts`](hooks::provide_crud_texts):
[`CrudUiTexts::english`](config::CrudUiTexts::english), [`CrudUiTexts::german`](config::CrudUiTexts::german) (the
default), texts of your own, or a signal to switch the language while the page is shown:

```no_run
# crudkit_leptos::__doc_example!();
#[component]
fn Localized(children: Children) -> impl IntoView {
    let german = RwSignal::new(false);
    provide_crud_texts(Signal::derive(move || {
        if german.get() { CrudUiTexts::german() } else { CrudUiTexts::english() }
    }));
    children()
}
# fn main() {}
```

# Styling

CrudKit renders no styles: style the atoms' default classes and data attributes, or pass `classes` (e.g. utility
classes) to individual atoms and to the `*_classes` props of iterators and `CrudFormLayout`. Each atom documents its
default classes and data attributes; atoms built on a Leptonic atom also carry its classes and data attributes (e.g.
`leptonic-Button` with `data-hovered`, `data-pressed`, `data-focus-visible`, `data-disabled`, `data-pending`), which
Leptonic documents. A stylesheet typically covers:

```css
/* The table: sort direction, selection, keyboard focus, and right-aligned numbers. */
.crudkit-TableColumnHeader[data-allows-sorting] { cursor: pointer; }
.crudkit-TableColumnHeader[data-sort-direction="ascending"]::after { content: "↑"; content: "↑" / ""; }
.crudkit-TableColumnHeader[data-sort-direction="descending"]::after { content: "↓"; content: "↓" / ""; }
.crudkit-TableRow[data-selected] { background: #eef4ff; }
.crudkit-TableRow[data-hovered] { background: #f6f8fa; }
:is(.crudkit-TableRow, .crudkit-TableColumnHeader, .crudkit-TableCell)[data-focus-visible] {
  outline: 2px solid #0969da;
  outline-offset: -2px;
}
:is(.crudkit-TableCell, .crudkit-TableColumnHeader)[data-kind="number"] { text-align: right; }
.crudkit-Value[data-empty]::before { content: "-"; content: "-" / ""; }

/* Statuses stay rendered while there is nothing to explain: collapse them, do not hide them. */
.crudkit-ListStatus { padding: 1.5rem; text-align: center; }
.crudkit-ListStatus[data-status="ready"] { padding: 0; }
.crudkit-ListStatus[data-status="failed"] { color: #cf222e; }

/* Pagination, forms, and fields. */
.crudkit-PageButton[aria-current="page"] { font-weight: 700; }
.crudkit-EditForm[data-dirty] h2::after { content: " ●"; content: " ●" / ""; }
.crudkit-FormGroup { display: grid; gap: 1rem; }
.crudkit-FormGroup[data-columns="2"] { grid-template-columns: repeat(2, minmax(0, 1fr)); }
.crudkit-TextField[data-invalid] .leptonic-Input { border-color: #cf222e; }
.crudkit-FieldError { color: #cf222e; }

/* Dialogs and buttons, through the classes of the Leptonic atoms they build on. */
.crudkit-DeleteDialog { position: fixed; inset: 0; display: grid; place-items: center; background: #0006; }
.leptonic-Button[data-disabled] { opacity: 0.5; }
.leptonic-Button[data-pending] { cursor: progress; }
.crudkit-ActionButton[data-intent="danger"] { color: #cf222e; }

/* Configuration errors. */
:is(.crudkit-ViewError, .crudkit-MissingFieldRenderer, .crudkit-UnknownField) { color: #cf222e; }

@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}
```

Configuration errors show as `role="alert"` elements with the classes `crudkit-ViewError` (a view without a
renderer), `crudkit-MissingFieldRenderer` (a field of a custom type without a renderer), and `crudkit-UnknownField` (a
field the form's model does not have).

# Accessibility

Leptonic's atoms supply keyboard interaction, focus management, and ARIA semantics. The application keeps its markup
accessible around them:

- Icon-only buttons need an `aria_label`, e.g. `<CrudDeleteButton aria_label="Delete club">`.
- Name tables with `aria_label` or `aria_labelledby` when the resource name does not read well.
- Keep heading levels in order: views of a nested instance sit below the heading naming it in the parent.
- Style keyboard focus through `data-focus-visible`, so that mouse presses leave no focus rings.
- Mark decorative generated content as such, e.g. `content: "↑" / ""`, so that screen readers skip it.
- Keep status regions in the layout while empty (see [Styling](#styling)), so that status changes are announced.
- Respect `prefers-reduced-motion` in transitions and animations.

# Server rendering

Instances render on the server too, so pages hydrate without flashing: lists and loaded entities render their loading
state there, create forms their fields. Lists, counts, and entities load in the browser. Element ids come from
Leptonic's `use_id`, so they match between server and browser. Effects, e.g. the clamping of the current page, run in
the browser only.

# Beyond atoms

Everything atoms do is available as hooks, for markup the atoms do not cover: the list
([`use_crud_list`](hooks::use_crud_list)), the surrounding form ([`use_crud_form`](hooks::use_crud_form)) or form
state of your own ([`use_crud_create_form`](hooks::use_crud_create_form),
[`use_crud_edit_form`](hooks::use_crud_edit_form), [`use_crud_read`](hooks::use_crud_read)), a field
([`use_crud_field_binding`](hooks::use_crud_field_binding)) and its inputs
([`use_crud_text_input`](hooks::use_crud_text_input), ...), deletion ([`use_crud_delete`](hooks::use_crud_delete)),
leave confirmation ([`use_crud_leave_confirmation`](hooks::use_crud_leave_confirmation)), actions
([`use_crud_actions_state`](hooks::use_crud_actions_state)), navigation
([`use_crud_navigation`](hooks::use_crud_navigation)), the entity of the surrounding row or form
([`use_crud_entity`](hooks::use_crud_entity)), notifications ([`use_crud_notifier`](hooks::use_crud_notifier)), texts
([`use_crud_texts`](hooks::use_crud_texts)), and the instance itself ([`use_crud_instance`](hooks::use_crud_instance)).
A table of your own binds Leptonic's table hooks to the list with [`use_crud_table`](hooks::use_crud_table) and shows
entities with [`use_crud_row_fields`](hooks::use_crud_row_fields). Tabs of your own remember their selection with
[`use_crud_tab_selection`](hooks::use_crud_tab_selection).
[`provide_crud_instance`](instance::provide_crud_instance) mounts an instance in a component of your own, like
[`CrudInstance`](instance::CrudInstance).
